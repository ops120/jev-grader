# 基于 JEV 的智能改卷系统（JEV Grader）

基于 TypeSafe **JEV**（System One）的智能改卷系统：让 JEV 像考生一样逐题作答，
再按官方答案自动改卷——逐题判定、总分与得分率、错题清单、依据强弱全部摊开给人看；
也支持人工录入答案后改卷（客观题）。

三栏界面：**左栏题面 · 中栏答案 · 右栏 JEV 运算过程**。

> 这个项目关心的不是"AI 能不能答对"，而是**答案能不能被质疑和复核**——
> 每道题都留下判定依据、概率分布与置信度，并且会明确标出"这题我没依据"。

## 定位与路线图

- **只做选择题与判断题**（含多选）：每一题都给出可回放、可质疑的判定轨迹。
  主观题、解答题、填空题、听力与写作**不在产品范围内**——这类题目在题库里
  明确标注「不可作答」及原因，而不是假装能改。
- **第一期主打文科卷**：英语、行测（常识判断／言语理解／判断推理／资料分析）已实测跑通；
  政治、历史等同版式文科卷按「从 PDF 到可信题库」流程接入即可。
- **理科卷规划中**：数学（新Ⅰ卷）已作为**理科样板**跑通——MathType 公式卷的
  抄题、验收与改卷链路全部验证，更多理科卷在路线图上。

## 5 行跑起来

```bash
pip install -r requirements.txt
cp .env.example .env          # 填入自己的 JEV API Key
python src/server.py          # 打开 http://127.0.0.1:8848
python tests/run_all.py       # （可选）8 道零配额门禁自检，不需要题库与密钥
# 就这么多了——clone 后仓库里没有任何题库，服务照常启动
```

**仓库不含题库数据**（试题内容版权归原权利人，见文末），所以第一次打开时
左中右三栏是空的——这是**指引态而不是报错**：左栏给出"从一份 PDF 到可判定题库"
的四步引导，顶栏统计不会假装有数据，接口也不会用别卷的数据悄悄顶上。
把自有题库放进 `data/exam_*.json`（或在 `src/papers.py` 注册新卷）后刷新即可。

## 功能

- **三栏工作台**：题面（原文按句编号、可点击高亮）、答案、运算过程三栏联动。
- **判定轨迹可视化**：每题拆成若干原子判断（题型识别 → 证据定位 → 逐选项支持度 → 最终判定 → 干扰项），
  步骤默认折叠，标题行保留结论摘要（如 `最高 B 93%`、`S11`）。
- **动态回放**：步骤依次点亮、证据句在左栏自动定位、答案延迟到「最终判定」才揭晓。
  支持暂停／重播／单步／调速。**播放节奏为演示性质**，界面以「演示回放」徽章标注，
  播放结束给出真实的并发耗时与 token 用量。
- **题库体检**：题库自带的校验记录（`validations`）、损失账目（`meta.loss`）与
  独立核验状态（`meta.verified`）直接显示在界面上——「这份题库可信吗」有明确答案，
  而不是靠感觉。
- **答案汇总与自动改卷**：全卷总览，可粘贴官方答案表做对比（支持 `21 B`、`21:B`、多选题 `9 ABC` 等写法），
  输出总分、得分率、正确率与错题清单，支持「只看错题」。
- **多试卷支持**：顶栏切换，各卷的题库、轨迹、答案表相互隔离。

## 支持的试卷与实测结果

| 试卷 | 可作答 / 入库 | 已求解（有轨迹） | 判定结果 |
|---|---|---|---|
| 高考英语（全国卷） | 35 / 67 | 35 | 平均置信度 93% |
| 2026 国考行测（副省级） | 113 / 120 | 110 | 平均置信度 63% |
| 2026 国考行测（地市类） | 112 / 122 | 102 | 平均置信度 62% |
| 2026 国考行测（行政执法类） | 123 / 130 | 108 | 平均置信度 62% |
| 高考数学（新Ⅰ卷）· 理科样板 | 11 / 19 | 11 | **6 / 10 正确（60%）**，答案已独立核对 |

口径说明（**先读这段再看百分比**）：

- 修复"静默丢题"之后，行测三卷的入库题数从 110/104/108 上升到 120/122/130，
  可作答题数随之多出 3/10/15 道。**这 28 道新增可作答题尚未求解**（求解要花真实 API 配额），
  因此表中百分比只覆盖"已求解"那一列的题，不代表整份卷的水平。
- 行测的"入库题数"等于卷面各小节自述的应有题数，差额逐条记在题库的 `meta.loss` 与
  `validations` 里；不可作答的部分主要是**选项在原件里是图片**的图形推理题
  （副省级 7 题、地市类 9 题、行政执法类 7 题），它们现在以「不可作答：选项为图形」
  出现在账面上，而不是像早期版本那样静默消失。
- 数学卷 6/10 的样本很小（可独立核对的选择题只有 10 道），填空与解答题不在统计内。

## 诚实性约束（项目核心设计）

1. **JEV 不产出推理文本。** 它只返回类型化判定与概率
   （`choice` / `noul` / `score` + `probabilities` + `confidence`）。
   所以右栏是**结构化判定轨迹的可视化**，不是模型的思维链——不存在"它这么想的"这种话。
2. **告警不等于正确。** 系统有三个告警：`依据薄弱`（所有选项的支持度都低于 50%）、
   `两路判断分歧`（直接作答与逐选项支持度结论不同）、`低置信度`（自报置信度 < 50%）。
   数学卷实测的 4 道错题中**没有一道被这三个告警捕获**——第 1 题置信度 0.92、两路自洽，但答案是错的。
   「两路一致」只说明模型内部自洽。
3. **不可作答的题不猜。** 需要音频、需要生成数值或文本、选项本身是图片的题一律标注原因，不做填充。
4. **缺数据不静默回退。** 未注册的试卷 id 直接给指引态，不会悄悄换成默认卷的数据；
   题库文件缺失给出"去跑抽取"的指引而不是 500；轨迹格式变更时旧轨迹标记为
   「轨迹过旧」，而不是按新格式误读。
5. **抄题模型无权给自己盖章。** `src/extract/verify.py` 是纯代码验收器：
   模型抄回的每道题都要带着定位锚点回到 PDF 原文上做双向比对（漏抄/编造都要抓），
   公式必须有非文本层墨迹物证。任何 error 都会挡住 `meta.verified`。

## 从 PDF 到可信题库

本项目真正的技术难点不在调用接口，而在**把 PDF 变成可信的结构化题目**。
每份试卷的"坏法"不同，需要不同手段：

| 试卷 | 问题 | 处理方式 |
|---|---|---|
| 英语 | 版式规整，但 `pdftotext` 会丢中文 | 用 PyMuPDF；逐题裁原图保真 |
| 数学 | MathType 排版，**分数线／根号／括号不在文本层里**（`1+5i i` 实为 `(1+5i)i`、`7 倍` 实为 `√7` 倍） | 文本层取中文与题号；公式由**人工**对着 200 DPI 的按题裁图逐题写成 LaTeX，机器只做弱校验。**公式写错查不出、编造中文也查不出**，所以本题库的 `meta.verified` 为 false，需独立验收才能盖章 |
| 行测 | 页面被重复绘制导致文本层系统性重复（`A.不谋而合谋而合`）、选项跨行、卷首注意事项也带编号 | 字符串层重复折叠（保留下划线，以免把填空横线 `________` 折成 `__`）、跨行副本剔除、选项续行拼接、遇到「第一部分」才认作开考 |

对**没见过的版式**，还有一条通用路径：`src/extract/transcribe.py` 用多模态模型
按协议抄题（每题自带原文锚点 probe），`src/extract/verify.py` 再用纯代码把草稿
钉回 PDF 逐题验收——锚点定位、区域切分、漏抄/编造比对、公式物证检查、
损失账目核对全部机器把关。配套 CLI：

```bash
python -m extract.transcribe --pdf <试卷.pdf> --out data/exam_new.json   # 抄题 + 验收 + 出库
```

> 解析过程中也查实了试卷本身的缺陷，均如实记录在体检报告里而非忽略。
> 例：英语卷完形填空原文有源文件错字（`he be loved home` 应为 `the beloved home`，两种提取器交叉验证确认）；
> 数学卷文本层把第 15 题的「疾病」错误映射成「乘病」，且卷首自述为「回忆版，可能会有些许错误」。

## 求解

```bash
python src/solver.py                              # 英语卷，全部可作答题目
python src/solver.py --paper math                 # 数学卷
python src/solver.py --paper xc_zf 1 2 3          # 行测行政执法类，只求解指定题号
python src/solver.py --paper english 21 --force   # 忽略缓存重算
```

轨迹写入 `data/traces*/`。**求解会消耗 API 配额**，全量求解前请先估算
（行测单份约 24 万 token、60 秒）。缓存按"载荷内容指纹"认领，
题库重编号后不会把别的题的判定当成这道题的答案。

### 独立核对（数学卷）

```bash
python src/verify_math.py   # 与独立算出的答案比对，结果写入 data/math_verification.json
```

## 目录结构

```

  parse_pdf.py        英语卷解析
  parse_math_pdf.py   数学卷解析（MathType 公式专用通道）

  bank.py             题库信封（exam*.json）的唯一构造器：schema、校验记录、损失账目
  extract/            通用抽取层：transcribe（多模态抄题）+ verify（纯代码验收）+ geometry
  judge/              判定编排：spec（判据表与措辞）+ engine（构造载荷）+ strategies（组合算术）
    specs/*.json        英语／数学单选／数学多选／行测四份 spec
  jev_client.py       JEV 客户端（Bearer 鉴权、429/529 指数退避）
  solver.py           并发求解与轨迹落盘
  papers.py           试卷注册表（题库路径 + 用哪份 spec）
  server.py           FastAPI：静态资源 + /api/*
  verify_math.py      数学答案独立核对
web/                  三栏前端（原生 ES 模块，无构建步骤；KaTeX 已内联于 web/vendor/）
tests/                八道零配额门禁：python tests/run_all.py
                      build 基线哈希 / 历史请求重放 / compose 对拍 / 判定契约 /
                      全路径重放 / 缓存身份 / 题库构造层 / 抽取层
                      （其中三道不需要本机题库，clone 后即真实生效）
data/                 题库与轨迹（不入库，由脚本生成本地副本）
```

## 三道不依赖题库的门禁

`python tests/run_all.py` 汇总的门禁里，`test_bank`、`test_extract`、
`test_judge_contract` 不需要任何题库文件就能真实生效——它们分别钉住
题库构造层（含每条校验记录的登记与渲染）、抽取验收器（fixture PDF 现造）
与判定编排契约。缺题库时其余门禁会打印 **SKIP：那不是通过，是未生效**，
汇总里会如实列出。

## 已知限制

- **行测的图形推理等小节不可作答**，因为它们的**选项在原件里是图片**，文本层里一个字母都没有
  （副省级 7 题、地市类 9 题、行政执法类 7 题）。这类题以条目保留并写明原因，不再静默删除。
- **行测答案受源文件限制**：副省级那份「答案解析」只给了 52/135 题的答案，
  因此该卷正确率**只能覆盖已公开答案的部分**，不代表全卷水平。
- **英语卷与数学卷的原件没有答案表**，正确率需人工录入答案后才能计算。
- **数学卷 60% 的样本很小**（10 道可核对的选择题），填空题与解答题不在统计内。
- 行测部分小节名为空或取自错误行（"（共N题）"上一行的启发式），属显示问题。
- 抄题端点（`src/extract/transcribe.py`）需要单独的多模态模型配置
  （`TRANSCRIBE_BASE_URL` / `TRANSCRIBE_MODEL` / `TRANSCRIBE_API_KEY`），
  与 JEV 判定接口相互独立。
